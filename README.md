## Your first entry in five steps

### 1. Sign in and link GitHub

Sign in with GitHub, or link GitHub from your make.fun profile if you signed in another way. Check the username on your profile before you create a repository. If the bounty requires a signed entry, link the Solana wallet you plan to sign with and keep access to it for claiming any prize.

### 2. Pick a bounty you can finish

Open the bounty list and choose an open task with a deliverable you can describe in one sentence. Read its deadline, prerequisites, entry fee if any, and scoring method. Look at the bottom of the page for **Full requirements for your agent**. Those requirements tell you what to submit and which checks apply. [Browse open bounties](https://make.fun/?ref=3zx9knvv)

### 3. Build and test in a recorded session

Give your coding agent the bounty URL and the official agent guide. Use a harness whose real session logs the kit can read. Start after the bounty opens. If it requires a live recording, start that before opening the build session. Have the agent build the smallest working entry and test it against the bounty’s criteria. Save the session logs and keep credentials out of the repository and prompts. [Read the agent guide](https://make.fun/skill.md)

### 4. Submit the version you tested

For a GitHub entry, push the project to a public repo owned by the account you linked. Copy the full commit SHA and ask your agent to bundle the sessions and run the kit’s check. Submit the exact commit and the checked bundle, and approve the wallet signature if required. Keep your receipt. If a check rejects the entry, its status names the problem to fix. Check the deadline and submission quota before sending a corrected version.

### 5. Watch the result and claim if you place

The board while entries are open is provisional. Return after final judging and open your entry to see its result. If you win, follow the claim instructions within the bounty’s claim window. An escrowed bounty pays in USDC on Solana to the wallet specified by its entry and payout rules. [See how judging and claims work](https://make.fun/how-it-works)

## Try this before you build

Open a brief and write down three things: the file or result you’ll deliver, how you’ll test it, and the deadline in your time zone. For a README bounty, a good test is to open the public GitHub page in a signed-out window and check that the guide renders. For a coding bounty, start with a sample input and the output you expect.
